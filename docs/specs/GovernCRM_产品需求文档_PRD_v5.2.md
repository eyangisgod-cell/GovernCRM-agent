## 二、业务背景与问题定义

### 2.1 业务背景

企业沉淀了大量"**沉睡但有价值**"的客户资产：买过一次再没回来、咨询过未成交、线下老客、服务到期未续。这批客户的盘活长期依赖人工，存在三个结构性问题：

| 问题           | 现状                                  | 后果             |
| ------------ | ----------------------------------- | -------------- |
| **盘不动：人力不够** | 运营 2–5 人面对数千至数万沉默客户，只能挑头部做          | 长尾客户永久沉没       |
| **盘不准：靠经验**  | 谁该唤醒、什么时候唤醒、用什么权益，靠运营个人经验，人员一换就失效   | 经验不沉淀，效果不可复现   |
| **盘不安全：无约束** | AI 生成话术直接群发；重复触达、过度触达、承诺超权限；出事后无法举证 | 品牌损伤、合规风险、无法追责 |

**监管背景（合规准入，非加分项）**：

| 法规 | 施行/发布 | 对本产品的直接要求 |
| --- | --- | --- |
| 《通信短信息服务管理规定（修订）》 | **2026-05-01 施行** | 未经明示同意不得发送商业短信；**授权记录须可核查**——对应本产品知情同意（C4，含 consent 三字段与 NO_CONSENT 强制校验）、审批责任链（FR-26）与 append-only 审计（FR-27） |
| 《人工智能拟人化互动服务管理暂行办法》 | 2026 年发布 | 直接约束 AI 外呼与拟人化交互——对应本产品通道能力声明（FR-31）、合规审查（FR-22）与"平台规则内触达"（P2 红线） |
| 《个人信息保护法》 | 2021 施行 | 明文零落库、最小必要、可删除（C1/C2/C6），最高罚 5000 万或营业额 5% |

> 触达类营销的合规要求已从"最佳实践"升级为**准入门槛**：授权可核查、决策可举证、AI 交互受约束是本产品设计的前提条件而非附加卖点。

**适用边界声明**：

| 适用 | 不适用 |
| --- | --- |
| 多平台经营（如淘系 + 抖店 + 私域并存）的品牌商家；有线下/存量 CRM、工单数据需融合决策的企业；有合规举证与审计要求的品牌方与代运营（TP） | **仅在单一平台站内经营、无审计要求的中小商家——平台官方免费工具已足够，本产品不适合** |

### 2.2 三个问题定义

| #      | 问题                           | 本产品的回答                            |
| ------ | ---------------------------- | --------------------------------- |
| **P1** | 如何让**有限的运营人力**盘活**大规模**沉默客户？ | 数字员工承接重复盘活动作，人类只处理例外与审批           |
| **P2** | 如何让盘活**经验可沉淀、可复用、可进化**？      | 执行循环 + 记忆 + 技能蒸馏：每次盘活的经验自动变成可复用技能 |
| **P3** | 如何让**自主执行**仍**可控、可举证、可问责**？  | 策略内核作为强制闸门；全链路审计 + 决策回放 + 熔断      |

### 2.3 明确不做的事

| 不做                        | 原因                                      |
| ------------------------- | --------------------------------------- |
| 不做平台爬虫 / 不抓取抖音淘宝公开数据      | 违规且不稳定                                  |
| 不伪造真实用户数据                 | 演示数据一律打 `_synthetic: true` 标记           |
| 不承诺"复购率提升 X%"             | 无对照实验，只能给相关性                            |
| **不做站外导流**（包裹卡引流、私聊加微信）   | 平台检测引流词并降权，2026 年判违规                    |
| **不用明文手机号做站外群发**          | 淘系/抖店密文与虚拟号机制已关闭该路径；不合法                 |
| **不把跨平台归集用于跨平台投放**        | 红线 P3：归集仅用于"避免重复打扰"，不是"把 A 平台客户拿到 B 营销" |
| **不做通用 Agent 护栏（危险工具拦截）** | 已有成熟开源实现（见架构文档第 3 章），本项目只做业务语义层治理       |
| **不重做平台已有的站内执行能力**        | 站内触达、客服、会员权益复用平台官方通道；本产品做平台结构性不做的中立层（跨平台频控、企业举证链、内外数据融合） |

**开发范围口径（裁决 #1）**：**PRD 全量功能为最终目标，分阶段交付；MVP 阶段先实现 M1（= v0.1，模拟数据 + 模拟发送跑通 15 步 SOP，可演示）。** 非 M1 功能一律做**架构与数据模型级预留（不可丢弃）**；范围裁剪只作用于"实现时序"，不作用于"是否实现"。

## 三、产品定位

### 3.1 定位声明

> **GovernCRM 是可定制的客户盘活数字员工平台。**
>
> 它把"沉睡客户唤醒"这件事，从**人工经验驱动**变成**Agent 自主执行 + 治理闸门约束 + 经验自动沉淀**。

一句话对外表述：

> **让每个运营都有一队会干活、守规矩、越用越强的数字员工。**

### 3.2 三条产品边界

| 边界                 | 含义                                                |
| ------------------ | ------------------------------------------------- |
| **① 不重做平台已有的执行能力** | 平台内触达、客服、会员权益一律复用平台官方通道，本产品不拥有通道                  |
| **② 自主不等于放任**      | Agent 可自主规划与执行，但**放行权在纯代码策略内核**；抑制规则任何人（含 AI）不可绕过 |
| **③ 先模拟、后真实**      | **MVP 版本使用模拟数据跑通全流程；后续版本接入真实电商平台与企业内部系统数据。** 真实对接需企业主体资质，故设计为可替换的传输层：模拟实现与真实实现共用同一协议，切换只换传输层 |

**研发口径（开源基座策略）**：本项目采用"**成熟开源库组合 + 契约级借鉴 + 业务层自研**"——编排/检索/API 框架等使用成熟开源库（MIT/Apache 系），对同类开源项目仅借鉴设计思想与接口契约、不复制源码；数据模型、策略内核、执行循环、治理层全部自研。**所有借鉴项目在动工前必须完成 LICENSE 核对并记录结论（见 R10）。**

### 3.3 与 v4.0「控制平面」的承接

```
v4.0 控制平面（该不该发、谁批、发完怎么证明）
        ↓ 保留，下沉为
v5.x 执行循环的强制闸门
        ↓ 外包一层
数字员工自主循环（规划 → 工具调用 → 记忆 → 反思 → 进化）
```

> **关键设计**：治理不是"Agent 之外的另一个系统"，而是**嵌在循环里的闸门**。Agent 每提出一个动作，必须先过闸门才能执行。

## 五、用户故事

### Epic A：数字员工配置（U1/U3）

| ID | 用户故事                                          | 验收（Given-When-Then）                                                  |
| -- | --------------------------------------------- | -------------------------------------------------------------------- |
| A1 | 作为运营负责人，我希望能**创建一个数字员工**，指定它的角色、负责的客户范围与可用技能  | Given 我是运营负责人 When 我选择"沉睡唤醒专员"模板并设定客户范围 Then 系统生成一个数字员工实例，带默认技能包与策略包（种子规则包见 6.4） |
| A2 | 作为运营专员，我希望能**给数字员工下达自然语言任务**（如"唤醒 90 天未购的老客"） | Given 数字员工已创建 When 我下达任务 Then 系统返回**执行计划**（分几步、用哪些工具、影响多少客户）供我确认；**计划确认与自主度等级解耦、任务级、一次性、所有等级（L0–L2）必需**——L2/L3 仅免动作级审批，不免计划确认；确认计划 = 批准影响面，是"影响面知情同意"入口与防注入的第一道人工闸门，并与任务级批量审批（FR-26）衔接（裁决 #7） |
| A3 | 作为运营负责人，我希望**调整数字员工的自主度**（全自动 / 需审批 / 只建议不动手） | Given 数字员工运行中 When 我把自主度从 **L1 改为 L0** Then 后续同类动作全部转为**仅建议**；已排队动作按新策略重新判定；**降级立即生效**，无需满足晋级标准；晋级/降级留审计（裁决 #6；与 FR-28 熔断恢复语义对齐） |

### Epic B：客户盘活执行（U1/U2）

| ID | 用户故事                            | 验收                                                            |
| -- | ------------------------------- | ------------------------------------------------------------- |
| B1 | 作为运营专员，我希望系统**自动识别该唤醒的客户**并给出理由 | Given 存在 90 天未购客户 When 执行盘活任务 Then 每个候选客户附带"为什么是他"的规则 ID 与维度值（种子九宫格分层，见 6.4） |
| B2 | 作为运营专员，我希望**同一客户在多平台不会被重复触达**   | Given 客户在淘宝与抖店同时存在（或同一 72h 冲突窗口内多平台动作并存）When 两侧均生成触达动作 Then 按附录 D 优先级只放行 1 条，另一条记录抑制原因（冲突窗口定义见 FR-20，裁决 #14） |
| B3 | 作为销售，我希望拿到**可直接使用的跟进话术**        | Given 客户被判定为可触达 When 我打开客户卡 Then 看到话术候选 + 证据引用 + 合规检查结果（话术来自种子话术模板，见 6.4.3） |
| B4 | 作为运营专员，我希望**高风险客户自动不被触达**       | Given 客户命中抑制红线（高投诉/高退款/明确拒绝）或**无授权（NO_CONSENT）**或 **Top 1% 高价值（SUP_HIGH_VALUE）** When 生成动作 Then 自动触达决策为 DENY，且我**无法强制放行**；SUP_HIGH_VALUE 命中者转人工跟进队列（裁决 #13/#15） |

### Epic C：治理与举证（U3/U4）

| ID | 用户故事                              | 验收                                                    |

## 六、核心业务流程

### 6.1 MVP 主链路：客户激活自动营销 SOP

> **这是 MVP（M1）必须跑通的完整流程，也是唯一要求"可演示、看得到真实效果"的流程。MVP 阶段全链路使用模拟数据与模拟发送；后续版本接入真实平台与企业系统数据后，本流程不变，仅传输层替换。**

```
① 下达任务（自然语言）："唤醒 90 天未购、历史消费 ≥500 元的老客"
        ↓
② 意图识别与路由（Jev 快判断）→ 确定任务类型 + 所需工具集 + 是否需要 LLM 规划
        ↓
③ 规划（LLM 慢思考，LangGraph）→ 拆解为可执行步骤序列
        ↓
④ 计划确认（任务级、一次性、所有自主度等级必需，裁决 #7）
        ↓
⑤ 取数（工具调用 / MCP）：客户分群 → 分层（种子九宫格，见 6.4.1）→ 候选名单
        ↓
⑥ 数据质量门禁 ──不合格──→ 隔离区（零 AI 调用，可审计证明）
        ↓
⑦ 身份匹配（确定性三档：高→归集 / 中→复核 / 低→保留独立，见 FR-15）
        ↓
⑧ 策略内核判定（纯代码）：是否触达 / 通道 / 自主度 / 是否抑制
        ↓
⑨ 跨平台冲突消解（72h 冲突窗口，附录 D）+ 全局频控（7 天 ≤2 次 + 同通道 72h）
        ↓
⑩ 内容生成（LLM）+ 合规审查（Jev 校验 + RulePack 规则 + consent 校验 NO_CONSENT）
        ↓
⑪ 治理闸门：ALLOW / REQUIRE_APPROVAL / DENY
    ★ 闸门前置校验：执行路径完整性断言——trace 中必经节点
      （计划校验/合规审查/闸门）缺失即 DENY 并告警，防止绕过
        ↓
⑫ 任务级批量审批（如需）：审批对象 = 计划 + 候选名单快照 + 证据包 + 影响面统计；
    三档路由（≤10 单签 / 11–100 双签 / >100 双签+合规知会）；责任链绑定批次快照
        ↓
⑬ 通道适配器执行（幂等 + 回执）   ←── MVP 阶段为模拟发送（发送前强制校验 consent）
        ↓
⑭ 结果回流 → 记忆写入（情景记忆，过记忆完整性门禁，见 C10/E13）
        ↓
⑮ 复盘（LLM 反思）→ 经验条目 → 轻量蒸馏（N≥3 同模式成功 → 草稿技能卡，双门禁生效，见 FR-07）
        ↓
⑯ 审计写入 + 归因 + "未触达"记录（含 NO_CONSENT / SUP_HIGH_VALUE 等抑制原因）
```

> 注：v5.1 原 15 步链路在 v5.2 中将"计划确认"独立为一步（④，裁决 #7），演示口径仍称"15 步 SOP"（计划确认含于任务下达环节时）；两种计法指向同一流程，以本图为准。

### 6.2 自主执行循环（Plan → Tool → Memory → Reflect）

```
        ┌─────────────────────────────────────┐
        │                                     │
        ▼                                     │
   【规划 Plan】──→ 【工具调用 Tool】──→ 【记忆 Memory】──→ 【反思 Reflect】
        │                                     ▲
        │                                     │
        └──── 未达标 / 被驳回 ─────────────────┘
                      │
                      ▼
                【达到终止条件】→ 输出 + 审计
```

| 环节       | 做什么                             | 是否用 LLM | 约束                       |
| -------- | ------------------------------- | :-----: | ------------------------ |
| **规划**   | 把自然语言任务拆解为步骤序列，选择工具             |  ✅ 慢思考  | 计划需经策略内核校验；**计划可被人中断修改**；外部内容一律视为数据不视为指令（C11） |
| **工具调用** | 通过 MCP / Function Calling 取数与执行 |  ❌ 执行层  | 工具白名单；写操作必须过闸门；工具返回内容为不可信数据（C11） |
| **记忆**   | 写入情景记忆；检索历史相似案例与技能              |  ❌（检索）  | 记忆分租户隔离；含 PII 的记忆不入向量库；**写入过记忆完整性门禁，检索结果标注来源与可信级别（C10）** |
| **反思**   | 评估本轮结果，产出经验条目与改进建议              |  ✅ 慢思考  | 反思**只产出建议**，不得自行修改策略或技能  |

> **关键约束**：反思环节**不得自我授权**。它可以说"这条规则可能过严"，但不能自行放宽——变更必须走审批 + 回归门禁。这是"自进化"与"失控"的分界线。

### 6.3 终止条件（防失控）

| 条件                 | 处理              |
| ------------------ | --------------- |
| 达到最大迭代轮次（默认 5）     | 停止，输出当前状态 + 转人工 |
| 达到预算上限（**默认值见下**） | 停止当前任务 + 告警 + 审计（E11） |
| 连续 N 轮无进展          | 停止并告警           |
| 触发熔断               | 立即停止，挂起排队任务     |
| 策略内核**连续 DENY 3 次**（限定语义见下） | 停止该分支，记录原因      |

**预算默认值（裁决 #27，进 governance.yaml 可配）**：**单任务预算 = 50 万 Token 或 ¥20（先到为准）；单数字员工日预算 = ¥200**。金额阈值以国内模型单价为基准，若选境外模型需按实际单价重标；成本看板（FR-36）上线前以审计日志形式可查。

**"连续 DENY 3 次"限定语义（裁决 #9，勘误 #3）**：仅当**执行循环内同一计划步骤（或同类动作提案）被连续 DENY 3 次**才终止该分支——目的是防 Agent 死循环重试。**批量判定阶段单客户 DENY 属正常业务结果，不计数、不触发停止**，正常进入"未触达"记录（FR-33）。

## 七、数字员工模型

### 7.1 数字员工的构成

一个数字员工 = **角色定义 + 技能包 + 策略包 + 记忆空间 + 自主度等级**

| 组成部分      | 内容                                         | 可配置性          |
| --------- | ------------------------------------------ | ------------- |
| **角色定义**  | 名称、职责、服务对象、语气风格、禁止事项                       | 运营可配（模板 + 编辑） |
| **技能包**   | 可调用的工具集 + 可复用的 SOP 技能卡片                    | 运营勾选，实施可扩展    |
| **策略包**   | 分层规则、抑制规则、频控、品类周期、合规规则包（种子内容见 6.4.1）        | 运营配置，需审批      |
| **记忆空间**  | 该员工的经验库（按租户 + 角色隔离）                        | 自动积累，可清理      |
| **自主度等级** | **L0 只建议 / L1 白名单内自动其余审批 / L2 ALLOW 全自动（仍审计）/ L3 不建议开放**（**与 7.2 语义一致**，勘误 #1 / 裁决 #4） | 负责人配置         |

### 7.2 自主度分级（与治理闸门绑定；**本表语义为全文唯一权威口径，裁决 #4**）

| 等级   | 含义                    | 适用场景          | 默认 |
| ---- | --------------------- | ------------- | :-: |
| **L0** | 只生成建议，不执行             | 新数字员工试用期、高风险品类 | ✅ 新建默认 |
| **L1** | 白名单内动作自动，其余需审批         | 常规盘活          | 推荐稳定态 |
| **L2** | 策略判定 ALLOW 的动作全自动，仍需审计 | 成熟场景、低风险动作     | —  |
| **L3** | 全自动含策略自动调优            | **不建议开放**，仅实验   | ❌  |

> **MVP（M1）开放范围限定（裁决 #5）**：**MVP 仅开放 L0 + L1，且 L1 在 MVP 简化为全审批、无白名单豁免**（白名单豁免能力随 FR-37 于 v0.2 激活）；**L2 随 v0.2**（MVP 阶段 G1 晋级硬标准基于模拟执行计数，本不满足开放条件）；L3 不开放。

**晋级硬标准（升级必须同时满足，缺一不可）**：

| # | 标准 | 校验方式 |
| - | --- | --- |
| G1 | 同类型动作累计成功执行 **≥ 50 次** | 系统自动校验（执行记录） |
| G2 | 近 30 天该动作类型**人工修正/驳回率 < 5%** | 系统自动校验（审批与修正记录） |
| G3 | **评测集全量通过**（含应拒答样本） | 系统自动校验（最近一次 CI 评测结果） |
| G4 | **负责人审批，且审批材料附执行报告**（执行量/通过率/修正记录） | 人工审批，报告由系统自动生成 |

> 任一自动校验项（G1–G3）不达标时，升级入口不可用（置灰并显示差距）。**降级立即生效**，无需满足任何标准。晋级与降级操作全部写入审计。

> **G1/G2 计数口径（裁决 #22）**：**"同类型动作"= `action_type + channel` 组合**；**模拟回执 status=success 计入** G1/G2 统计，指标口径注明含模拟执行（数据带 `_synthetic: true`）；MVP 建 `worker_metrics` 表与计数逻辑，晋级 UI 演示随 M2（v0.2）；真实接入后计数器可按数据源分列，口径不变。

## 九、AI 使用边界（双模型：Jev 快判断 + LLM 慢思考）

### 9.1 核心原则：快慢分离

| 层        | 模型          | 负责                    | 特点                     |
| -------- | ----------- | --------------------- | ---------------------- |
| **快思考（前）** | **Jev 判断模型** | 意图识别、路由、工具选择、合规校验、风险分级 | 只返回结构化判断 + 概率；不生成文本    |
| **慢思考（后）** | **通用 LLM**   | 任务规划、话术生成、复盘反思、解释     | 生成能力强；成本高、延迟高          |
| **决策**    | **纯代码策略内核**  | ALLOW / REQUIRE_APPROVAL / DENY | **零 LLM、零 Jev，确定性可单测** |

> **一句话**：**Jev 负责"这是什么、该走哪条路"，LLM 负责"具体怎么说、怎么做"，代码负责"能不能放行"。**

### 9.2 逐环节是否用 AI

| 环节       | Jev | LLM | 纯代码 | 理由                    |
| -------- | :-: | :-: | :--: | --------------------- |
| 意图识别与路由   | ✅  | —  | 兜底   | 有限选项判断，Jev 主场；低置信降级   |
| 工具选择      | ✅  | —  | 白名单  | Jev 提速；白名单是硬约束        |
| 任务规划      | —  | ✅  | 校验   | 需生成能力；计划须经策略内核校验      |
| 客户分层      | —  | —  | ✅   | 必须可解释、可复现、可问责         |
| 身份匹配      | —  | —  | ✅   | 错误合并代价极高；确定性三档口径（FR-15） |
| 冲突消解      | —  | —  | ✅   | 确定性优先级（附录 D）          |
| 策略判定      | —  | —  | ✅   | **核心原则：决策必须可测试**       |
| 话术生成      | —  | ✅  | —   | AI 强项，失败可拦截            |
| 合规审查      | ✅  | ✅  | ✅   | 三保险：Jev 快检 + LLM 审 + 规则包终裁 |
| 复盘反思      | —  | ✅  | —   | 只产建议，不得自行改策略           |
| 技能蒸馏（轻量，M1） | —  | ✅  | 门禁   | 生成后必须过回归评测 + 人工确认双门禁   |
| 效果归因      | —  | —  | ✅   | 统计计算                   |

### 9.3 Jev 的使用约束（必须遵守）

> Jev 是 2026-09 发布的新型"判断模型"（TypeSafe AI 的 System One Model），输出 Choice / Score / Noul 三种原语并带概率。它的价值是**把高频判断从 LLM 里摘出来**，但有以下硬约束：

| #      | 约束                                     | 应对                             |
| ------ | -------------------------------------- | ------------------------------ |
| **J1** | **CJK 准确率低于英文**（官方文档与第三方评测均提到）          | 中文场景必须设置更低置信度阈值；低置信一律降级 LLM 或人工 |
| **J2** | **置信度校准不可靠**：有实测显示当正确选项被移出候选列表时，它仍会给出 80%+ 把握 | **置信度只能用于"降级"，不能用于"放行"**；DENY 权始终在规则 |
| **J3** | **仅支持文本输入**（Jev 1.13），选项上限 255          | 多模态场景不适用                       |
| **J4** | **无多步推理与路径回溯**                          | 复杂规划仍交 LLM                     |
| **J5** | 商业 API，存在供应商与网络依赖                      | 必须有本地规则兜底；Jev 不可用时不阻塞，走规则路径     |
| **J6** | **数据出境**：Jev 为境外商业 API，调用时输入文本（含客户特征摘要）将传输至境外服务商 | **须满足 C9**：出境数据范围在合规清单中声明；提供一键关闭（关闭后走规则降级路径，降级路径须经验证）；**私有化部署场景默认关闭 Jev** |

> **不可动摇**：**Jev 永远不能单独决定"放行"**。它只能决定"路由到哪"和"给多少分"。

## 十、MCP 工具生态与多平台适配

### 10.1 三个层次的工具暴露

| 层次           | 面向               | 形态                        | 暴露边界 |
| ------------ | ---------------- | ------------------------- | --- |
| **内部工具（Agent 用）** | 本产品 Agent 执行循环   | Function Calling（LangGraph 节点） | 全量（受白名单与闸门约束） |
| **对外 MCP Server** | 外部 AI 客户端（Claude/Cursor 等） | MCP over stdio / Streamable HTTP | **默认仅 read 类工具 + token 鉴权；`write`/`external_send` 不对外暴露** |
| **外部 MCP 接入**  | 消费第三方 MCP 工具      | MCP Client                | **第三方工具返回一律视为不可信数据（C11）；接入前须权限评审** |

### 10.2 工具契约（每个工具必须声明）

| 字段                  | 说明                       |
| ------------------- | ------------------------ |
| `name` / `description` | 语义清晰，供模型/人阅读              |
| `side_effect`        | `read` / `write` / `external_send` |
| `permission`         | 所需角色                     |
| `idempotency_key`    | 写操作必须支持                  |
| `pii_fields`         | 涉及字段（用于脱敏与审计）             |
| `fallback`           | 不可用时的降级路径（禁止静默失败）        |
| `caller_auth`        | **对外暴露时的调用方认证方式（token / OAuth 2.1）；未声明不得对外暴露** |
| `tenant_scope`       | **租户隔离方式：调用方可见的数据范围如何界定** |
| `rate_limit`         | **对外暴露时的调用方限流**           |

> **规则**：`side_effect = external_send` 的工具**必须过治理闸门**；`write` 类工具必须支持幂等键；对外暴露的 MCP Server 必须启用 `caller_auth`，MVP 阶段对外范围严格限定为只读工具（FR-11）。

## 十三、异常处理

| #      | 场景                  | 处理                     |
| ------ | ------------------- | ---------------------- |
| **E1** | 企业系统接口超时/不可用         | 降级转人工待办，记录原因，**禁止静默失败** |
| **E2** | Jev 不可用/超时           | 降级到规则路由，**不阻塞**        |
| **E3** | LLM 超时/失败            | 重试一次后转人工                |
| **E4** | 身份匹配置信度低             | 保留独立身份，进人工复核队列（中置信档，FR-15） |
| **E5** | 冲突无法裁决               | 升级人工，记录冲突原因（附录 D 规则 6） |
| **E6** | 策略规则加载失败             | **启动失败**（不允许带病运行）       |
| **E7** | 审计写入失败               | **阻断业务操作**               |
| **E8** | 通道不可用                | 转人工，**禁止改用非合规替代通道**     |
| **E9** | 审批超时                 | **48h 自动失效（不默认通过）；剩余 24h 升级提醒上一级**（裁决 #25） |

| **E11** | 预算超上限                | **停止当前任务 + 告警 + 审计**；默认值：单任务 50 万 Token 或 ¥20（先到为准）、单员工日 ¥200（裁决 #27） |
| **E12** | 技能蒸馏产出异常（如含 PII）     | 拒绝入库并告警                  |
| **E13** | **记忆写入门禁拒绝（疑似投毒/注入）** | **拒绝写入 + 告警 + 内容进人工审查队列；不阻断当前执行循环（该条记忆不生效即可）** |
| **E14** | **路径完整性断言失败（trace 缺失必经节点）** | **一律 DENY + 告警；该动作进人工审查** |
