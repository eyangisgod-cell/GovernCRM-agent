# 本地环境（三步起）

> 面向：第一次拉起仓库的新同事 + 演示前的环境准备。
> 权威：`docs/specs/MVP_任务拆解.md` §2 T0.1；依赖准入见 `LICENSES.md`。

---

## 三步起

```bash
# ① 装依赖（uv 三档依赖组：runtime / dev / evaluation）
uv sync

# ② 本地变量（只含占位符；真实口令由种子脚本写进本地 .env，不入库）
cp .env.example .env
#   Windows PowerShell: copy .env.example .env
#   编辑 .env：至少改 POSTGRES_PASSWORD 与 DATABASE_URL 里的同一份口令

# ③ 起数据库（PostgreSQL 16 + pgvector，三合一：关系 + SKIP LOCKED 队列 + 向量）
docker compose up -d
docker compose ps        # 期望 db 为 healthy
```

验证：

```bash
docker compose exec db psql -c "select extname from pg_extension where extname='vector'"
make check               # 本地与 CI 同一入口：test / lint / format-check / typecheck / pg-test
```

## 常用命令

| 命令 | 作用 |
| --- | --- |
| `make help` | 列出全部命令 |
| `make sync` | `uv sync` |
| `make up` / `make down` | 起 / 停数据库（`down` 保留数据卷） |
| `make migrate` | 按序应用 `migrations/*.sql`（幂等；Wave 0 唯一写者是 T0.2） |
| `make db-shell` | 进入 psql |
| `make test` | pytest（默认排除 `-m pg`） |
| `make pg-test` | 真 PostgreSQL 集成测试（需数据库已启动） |
| `make lint` / `make format-check` / `make typecheck` | ruff / ruff format --check / mypy |
| `make scan-deps` | 依赖白名单 + 零供应商依赖扫描（红线⑤） |
| `make check` | **全量门禁**，本地与 CI 同一入口 |

## 端口冲突怎么办

`docker-compose.yml` 的宿主端口取 `${POSTGRES_PORT:-5432}`。若本机 5432 已被其它 PostgreSQL 占用，
**改本地 `.env`** 里的 `POSTGRES_PORT`（例如 55432），并同步改 `DATABASE_URL` 中的端口，二者必须一致：

```bash
POSTGRES_PORT=55432
DATABASE_URL=postgresql+psycopg://governcrm:<口令>@127.0.0.1:55432/governcrm
```

容器内仍然是 5432，**不影响** `docker compose exec db psql ...` 这类命令。

> **主机名请写 `127.0.0.1`，不要写 `localhost`**：部分 Windows 环境下 `localhost` 先解析到 `::1`，
> 而 compose 只发布 IPv4 端口，IPv6 连接被静默丢包，表现为"连接卡 100 多秒才通"。

## 演示账号口令在哪

- 演示口令**不入库、不写进文档**：由 T0.4 的种子脚本随机生成并写入本地 `.env`。
- `.env.example` 里只有占位符（`CHANGE_ME_LOCAL_ONLY` 之类）。
- 前端 Mock 模式下的 4 个演示账号（admin / owner / operator / compliance）口令由种子脚本产出。

## 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `uv sync` 卡在下载 | 网络慢 | `UV_HTTP_TIMEOUT=180 uv sync` |
| `docker compose up -d` 报 `port is already allocated` | 宿主端口被占 | 改本地 `.env` 的 `POSTGRES_PORT` 后重起 |
| `psql: role "root" does not exist` | 未带用户名 | 容器已设 `PGUSER`/`PGDATABASE`；若自行进容器请加 `-U governcrm` |
| `vector` 扩展不存在 | 数据卷是旧的、初始化脚本没跑 | `docker compose down -v && docker compose up -d`（**会清空本地数据**） |
| `make check` 在 pg 环节失败 | 数据库没起 | 先 `make up`，再 `make pg-test` |
| 连库卡 100 多秒 | `DATABASE_URL` 用了 `localhost`（IPv6 被丢包） | 改成 `127.0.0.1` |
| `import litellm` 报白名单违规 | 业务层误引供应商 SDK | 改走 `src/providers/` 适配层的 `ModelProvider` / `JudgmentProvider` 协议 |

## 边界

- 本仓库 MVP 阶段跑的是**模拟数据 + 模拟发送**（数据标 `_synthetic: true`），不接真实电商平台。
- 策略内核、审计哈希链、路径断言在**后端真实实现**并由 CI 验证；前端 Mock 只承载演示交互。
- 演示口令、数据库口令一律只存在于本地 `.env`（已被 `.gitignore` 排除）。
